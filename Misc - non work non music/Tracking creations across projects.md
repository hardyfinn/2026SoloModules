# Tracking creations across projects

## Summary
Options for one list of modules and other creations across projects, from lightest to most automated; the pick was a shared Google Sheet or Doc tracker with a status column.
Each project adds its own rows to the shared sheet, and status is marked as New, Reviewed, In use or Retired.

## Question
> I'm having trouble keeping up with all the modules that we are making. I need a better way to compile a list from multiple projects on my account, preferably with a way to mark items as first reviewed or used. Please make suggestions.

## Answer
A few options, from lightest to most automated. I'm assuming "modules" means the mods and other things built across your projects. Tell me if you mean something else.

1. **Google Sheet or Doc tracker (my pick).** One row per item with columns for name, project, date made, a link, status (New / Reviewed / In use / Retired) and notes. Status is a dropdown, so marking something reviewed or used is one click. It works across every project, and you can sort and filter. I can build the first version.
2. **A tracker file in each project, rolled up by me.** I'd keep a simple list in each project's shared folder. A thread would then collect them into one master list on request. This keeps everything inside Claude, but the roll-up is manual.
3. **Notion, Airtable or similar via a connector.** Better if you want a board view, tags or reminders. It needs a connector set up first.
4. **Interactive checklist in a doc.** Checkboxes for "reviewed" and "used". It's the simplest, but weaker for filtering or many items.

Limit to know about: I can only see this project directly. Pulling in items from your other projects means either a thread in each one adding to the shared sheet, or you pasting a list in.

Want me to start with option 1? If so, which projects should it cover, and should I seed it with what's already in this one (the record label designs, sign icons, tax calculator and so on)?
